# DJgurda

Telegram-бот для переноса медиа по ссылке в чат.

При запуске и выключении бот уведомляет администраторов и работает через long polling.
В активном чате он классифицирует ссылки по источнику и типу, включая зеркала вроде
kkinstagram.com. Бот скачивает и отправляет в чат вместо исходного сообщения видео, Shorts и клипы
YouTube, видео TikTok, Reels Instagram и треки Яндекс Музыки; остальные типы пока отвечают
заглушкой. Пересланные сообщения самого бота повторно не обрабатываются. Чтобы удалять сообщения в группе, боту нужны права администратора на удаление.

По умолчанию медиа отправляется без подписи; кнопка в `/status` включает в чате подпись под
спойлером со ссылкой на источник и ником отправителя без упоминания (в личной переписке — только
источник). В командах, уведомлениях и ответах
об ошибках используются кастомные эмодзи из legacy-набора DJgurda. Для их отображения в личных
и групповых чатах Telegram требует Premium у владельца бота либо дополнительный username
через Fragment ([правила Bot API](https://core.telegram.org/bots/api#html-style)). Premium
действует только для сообщений, которые бот отправляет сам, поэтому в inline-режиме
используются обычные эмодзи.

| Команда | Действие |
| --- | --- |
| `/start` | Включить бота в чате |
| `/stop` | Приостановить бота в чате |
| `/status` | Статус бота, версия и кнопки запуска, остановки и подписи; на паузе — только запуск |
| `/help` | Команды и поддерживаемые источники |

В личной переписке, где бота нет, можно написать `@имя_бота ссылка` и выбрать результат;
в группах и каналах inline-режим отвечает отказом. Подпись в нём содержит только источник:
отправителя Telegram показывает сам. Кнопка под результатами открывает `/status` в переписке
с ботом, где подпись для inline и включается.
Уже скачанное видео отправляется сразу; новое приходит заглушкой, которую бот заменяет видео
после загрузки. Если сохранённое видео не отправляется, рядом есть результат «Скачать заново».
Для этого у @BotFather включаются `/setinline` и `/setinlinefeedback`, а бот добавляется
в чат `INLINE_CHAT_ID` с правом публикации.
В этот же чат без звука приходят ошибки доставки с диагностикой, чтобы их было видно без логов
сервера; в нём включено автоудаление сообщений, поэтому ссылки и ID чатов из ошибок не копятся.

## Границы

- Сценарий: ссылка → получение контента → отправка в Telegram-чат.
- База данных хранит конфигурацию чатов.
- Статистика не ведётся; данные из legacy не переносятся.
- Без Redis, внешнего брокера задач и веб-фреймворка.
- Без прикладного шифрования; секреты передаются через окружение.
- Репозиторий публичный.

## Конфигурация

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен Telegram-бота; отдельный для каждого окружения |
| `ADMIN_IDS` | Непустой JSON-массив ID администраторов, например `[123456789]` |
| `APP_ENV` | `development` (по умолчанию) или `production` |
| `DATABASE_PATH` | Файл SQLite; в Compose задан как `/data/djgurda.sqlite3` |
| `YANDEX_MUSIC_TOKEN` | Необязательный токен Яндекс Музыки; без него треки не скачиваются |
| `INLINE_CHAT_ID` | Необязательный ID канала или группы, куда inline-режим загружает новые видео и бот пишет ошибки доставки; без него inline работает только с ранее скачанными ссылками, а ошибки остаются в логах |
| `WORK_DIR` | Каталог временных загрузок; в Compose задан как `/data/work` |
| `LOG_LEVEL` | `DEBUG`, `INFO` (по умолчанию), `WARNING`, `ERROR`, `CRITICAL` |

Переменные процесса имеют приоритет над `.env`. Администратор должен заранее нажать Start в чате
с ботом, иначе запуск завершится ошибкой.

## Ветки

| Ветка | Назначение |
| --- | --- |
| `main` | Production: бот |
| `production-botapi` | Production: локальный Bot API; в него попадает через PR из `development` |
| `development` | Интеграция изменений; в `main` попадает через PR |
| `legacy` | Предыдущая реализация |

Маршрут: ветка от `development` → PR в `development` → PR в `main`.
Функции бота проверяются локально; на сервере development только проверяет деплой и затем
останавливается. Production работает постоянно. VM выделена исключительно под DJgurda;
бюджет бота и его Bot API описан в [инструкции деплоя](docs/DEPLOYMENT.md#budget).

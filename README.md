# DJgurda

Telegram-бот для удобного переноса медиа по ссылке в чат. Новая реализация начинается
с каркаса [AgentFleex](https://github.com/Duby67/AgentFleex/tree/c91a48f08cc011d89d3ddadf7fbe17a3a07d018b).
Минимальный бот отвечает `Hello world` на команду `/start` через long polling.
Обработка медиа и автоматическое развёртывание пока не реализованы.

## Локальный запуск

Требуются [uv](https://docs.astral.sh/uv/) и Python 3.14 (uv может установить его автоматически).

```bash
uv sync --locked
cp .env.example .env
# Укажи BOT_TOKEN в .env.
uv run --locked djgurda
```

После запуска отправь боту `/start` в Telegram. Для каждого одновременно работающего
окружения используй отдельный токен.

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Обязательный токен Telegram-бота |
| `APP_ENV` | `development` (по умолчанию) или `production` |
| `LOG_LEVEL` | `DEBUG`, `INFO` (по умолчанию), `WARNING`, `ERROR` или `CRITICAL` |

Переменные процесса имеют приоритет над `.env`. Токен нельзя добавлять в Git.

## Тесты

```bash
uv sync --locked
uv run --locked pytest -q
```

Тесты проверяют ответ на `/start`, отсутствие ответа на обычный текст и отказ запуска
без заполненного токена. Запросы к Telegram заменены заглушкой; локальный `.env` не читается.

## Границы новой версии

- Основной сценарий: ссылка → получение контента → отправка в Telegram-чат.
- База данных хранит конфигурацию чатов.
- Статистика пока не реализуется; данные из legacy не переносятся.
- Redis, внешний брокер задач и веб-фреймворк не используются.
- Дополнительное прикладное шифрование не предусматривается; секреты передаются через окружение.
- Репозиторий предназначен для публичного размещения.

## Ветки

| Ветка | Назначение |
| --- | --- |
| `main` | Production: целевая ветка для готовых обновлений и будущего production deploy |
| `development` | Накопление изменений новой версии; обновления попадают в `main` через PR |
| `legacy` | Сохранённая предыдущая реализация на коммите `4f1966e5dc3aa91fbf133666005434ddb655c48d` |

Рабочий маршрут: отдельная ветка от `development` → PR в `development` → PR в `main`.
Обязательное правило работы с ветками закреплено в [AGENTS.md](AGENTS.md).

Первый PR из `development` заменяет старое содержимое каркасом. История Git сохраняется,
чтобы ветки можно было сравнивать и объединять обычным PR. Старые deploy-workflows
удаляются вместе с legacy-кодом; production deploy новой версии нужно реализовать
вместе с приложением. `development` не развёртывается в production.

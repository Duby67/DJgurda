# DJgurda

Telegram-бот для удобного переноса медиа по ссылке в чат. Новая реализация начинается
с каркаса [AgentFleex](https://github.com/Duby67/AgentFleex/tree/c91a48f08cc011d89d3ddadf7fbe17a3a07d018b).
При запуске бот отправляет каждому администратору уведомление `Бот запущен` и
`Версия: <версия пакета>`, затем работает через long polling без ответов на сообщения.
Обработка медиа пока не реализована. CI проверяет PR; после слияния workflows
собирают образ и развёртывают соответствующее окружение. Настройка GitHub и сервера
описана в [инструкции развёртывания](docs/deployment.md#github-actions).

Docker-образ, Compose для production/development и бюджеты небольшой VM описаны
в [инструкции развёртывания](docs/deployment.md).

## Локальный запуск

Основной запуск в WSL — через Docker Engine / Docker Desktop с интеграцией WSL
и Docker Compose v2. Открой проект в окне VSCode WSL.

При первой настройке создай `.env` из `.env.example` (не перезаписывай существующий)
и заполни `BOT_TOKEN` и `ADMIN_IDS`.

В VSCode нажми **Ctrl+Shift+B** или выбери **Tasks: Run Task → DJgurda: Docker start**.
Задача собирает образ и запускает контейнер с development-ограничениями, показывая
логи в терминале. После изменений кода останови и запусти задачу заново: код входит
в образ, автоперезагрузки нет. Для остановки используй **Ctrl+C** в терминале;
задача **DJgurda: Docker stop** удаляет контейнер и сеть. Python-отладчик F5
к этому запуску не подключён.

Эквивалент из терминала WSL:

```bash
DJGURDA_IMAGE=djgurda:local docker compose --env-file .env \
  -f deploy/compose.yaml -f deploy/compose.development.yaml \
  -f deploy/compose.local.yaml up --build --force-recreate --remove-orphans
```

Останови ранее запущенный через Python экземпляр перед запуском контейнера
с тем же токеном.

Перед первым запуском каждый администратор должен открыть личный чат с ботом и
нажать Start, чтобы бот мог отправлять ему сообщения. Для каждого одновременно
работающего окружения используй отдельный токен. Ошибка отправки уведомления
прерывает запуск. Версия берётся из метаданных пакета, заданных в `pyproject.toml`.

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Обязательный токен Telegram-бота |
| `ADMIN_IDS` | Обязательный непустой JSON-массив ID администраторов, например `[123456789]` |
| `APP_ENV` | `development` (по умолчанию) или `production` |
| `LOG_LEVEL` | `DEBUG`, `INFO` (по умолчанию), `WARNING`, `ERROR` или `CRITICAL` |

Переменные процесса имеют приоритет над `.env`. Токен нельзя добавлять в Git.

## Тесты

Для локальных тестов требуются [uv](https://docs.astral.sh/uv/) и Python 3.14.
После `uv sync --locked` тесты доступны также в панели Testing VSCode;
интерпретатор — `.venv/bin/python`.

```bash
uv sync --locked
uv run --locked pytest -q
```

Тесты проверяют уведомления администраторам, отсутствие ответов на сообщения,
ошибки отправки и обязательные настройки. Запросы к Telegram заменены заглушкой;
локальный `.env` не читается.

## Границы новой версии

- Основной сценарий: ссылка → получение контента → отправка в Telegram-чат.
- База данных хранит конфигурацию чатов.
- Статистика пока не реализуется; данные из legacy не переносятся.
- Redis, внешний брокер задач и веб-фреймворк не используются.
- Дополнительное прикладное шифрование не предусматривается; секреты передаются через окружение.
- Репозиторий предназначен для публичного размещения.

## Ветки

| Ветка | Назначение |
| --- | --- |
| `main` | Production: готовые обновления и production deploy |
| `development` | Накопление изменений новой версии; обновления попадают в `main` через PR |
| `legacy` | Сохранённая предыдущая реализация на коммите `4f1966e5dc3aa91fbf133666005434ddb655c48d` |

Рабочий маршрут: отдельная ветка от `development` → PR в `development` → PR в `main`.
Обязательное правило работы с ветками закреплено в [AGENTS.md](AGENTS.md).

Первый PR из `development` заменяет старое содержимое каркасом. История Git сохраняется,
чтобы ветки можно было сравнивать и объединять обычным PR. Старые deploy-workflows
удаляются вместе с legacy-кодом; production deploy новой версии выполняет `.github/workflows/deploy.yml`. `development` не развёртывается в production.
